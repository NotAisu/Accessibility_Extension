Proven Rules Policy (ADR 0005)

A static accessibility rule reports blocking Findings only after it proves its precision on independently labelled code (W3C ACT Rules test cases, real open-source pages and components, and single-failure injections).

73 Proven rules

Verified per language across HTML, JSX, TSX, Vue, Svelte, Angular, and Astro.

100% measured precision

6,092 of 6,092 labelled cases correct (0 false positives) across all Proven rules in src/core/proof-status.json.

>= 95% Wilson lower bound

Every Proven rule meets a 95% Wilson lower confidence bound at 95% confidence before reporting Findings.

Rules that have not yet cleared that threshold, and criteria source code alone cannot decide (such as runtime contrast or 2.5.8 target size), are reported under Needs Review instead of silent passes or noisy false positives.

100% Local, Offline, and Zero-Execution Guarantees

  • No telemetry, no account, no tracking: Allyproof collects nothing and sends nothing about you or your usage. This documentation site loads zero JavaScript, zero analytics, and zero external resources.
  • Offline deterministic Check: The VS Code extension Check, npm CLI, GitHub Action, and local stdio MCP server make zero network requests and run no AI.
  • Zero workspace code execution: Your files are parsed statically and never executed. Your repository's own ESLint, TypeScript, or framework configs are never loaded or run.
  • Optional AI Review stays explicit: In VS Code, AI Review runs only when you start it (auto-on-save is off by default) and sends code only to GitHub Copilot or a local OpenAI-compatible model (LM Studio or Ollama). Untrusted workspaces lock down local endpoint settings.

Reproducible Proof & Agent Eval

Allyproof separates deterministic ground-truth verification (which runs on every commit in CI) from local LLM agent evaluations (which require model tokens and run on demand).

Verified deterministic ground truth

Every commit runs npm run verify, including the ground-truth gate on both source and the unpacked VSIX/npm bundles against labelled files in test/ground-truth/. Current verified evidence in src/core/proof-status.json: 73 Proven rules, 6,092 of 6,092 correct (100% measured precision, >= 95% Wilson lower bound at 95% confidence).

Measuring agent fixes with npm run eval:agent

To reproduce how a coding agent performs without vs. with Allyproof's local stdio MCP server and Skill on real ground-truth files, run the local harness:

npm run bundle
npm run eval:agent -- --dry-run --limit 1
npm run eval:agent -- --claude sonnet --limit 1

Each task places one ground-truth file in an isolated directory with allyproof mcp as its only MCP server (no shell, no web) and scores every run deterministically:

  • Fixed: labelled Findings the Check no longer reports.
  • Added: any new Finding introduced by the edit fails the run.
  • Integrity: the file must still parse and preserve its text and interactive/embedded elements (deleting content to silence a Finding fails).
  • Honesty: every claimed fix must match a Finding the Check reported before and no longer reports.
  • Cost: tool calls, tokens, and wall time per fixed Finding, written to out/agent-eval/report.json.

Because eval:agent depends on your chosen model and API/session tokens, it is never run in CI and this page publishes no synthetic or unverified LLM benchmark scores.
